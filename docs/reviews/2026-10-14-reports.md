### Findings, most important first

1. **Medium: the Clip "Play" button does nothing after the browser blocks autoplay.** That case (for example iOS Low Power Mode) is the reason the button exists.
   - **Evidence:** `src/lib/components/Clip.svelte:30,35-40`. `wanted = chosen ?? (motion.on && !saveData)` is already `true` when autoplay is refused. The tap sets `chosen = true`, so `wanted` doesn't change and the effect never calls `play()` again.
   - **Verified:** in Playwright with `play()` rejecting, the play count stayed at 1 after the tap and the video stayed paused.
   - **Fix:** call `video.play()` directly inside `toggle()`. That also keeps the user gesture. Then drop the unused `refused` state.
   - **Effort:** S

2. **Medium: the contact endpoint has no rate limiting and no origin check.**
   - **Evidence:** `api/contact.js:33-52`. A hidden honeypot field is the only defence.
   - **Scenario:** a script POSTs in a loop, floods studio@ and burns the Resend quota. Real messages then fail with `send-failed`.
   - **Fix:** reuse the Upstash Redis already in the project. Apply a per-IP counter, the same pattern as `RECORD_EVENT`, for example 5 per 10 minutes. Optionally reject a foreign `Origin` on JSON requests.
   - **Effort:** S–M

3. **Low–medium: the honeypot field is named `company`, which browser autofill may fill.**
   - **Evidence:** `ContactForm.svelte:56` and `api/contact.js:36`.
   - **Scenario:** Chrome or Safari address autofill maps a field called `company` to organization and may fill it even though it's off-screen. A real lead's message is then dropped silently while the page says "Sent". This depends on the browser; I couldn't reproduce autofill headless.
   - **Fix:** give the field a name with no autofill meaning, and log honeypot hits.
   - **Effort:** S

4. **Low: the contact endpoint crashes on unusual input or a network failure.**
   - **Evidence:** `api/contact.js:22,36,45`.
   - **Verified:** a JSON body of `null` throws `TypeError: Cannot read properties of null (reading 'company')`, which becomes a 500.
   - **Also:** the `fetch` to Resend has no try/catch and no timeout. A network error or hang gives a raw Vercel error page to visitors without JavaScript, and can hang until the function times out.
   - **Fix:** guard `data` with `if (!data || typeof data !== 'object')`. Wrap the fetch in try/catch with `AbortSignal.timeout(8000)` and answer `send-failed`.
   - **Effort:** S

5. **Low: the name and email fields accept odd characters.**
   - **Evidence:** `api/contact.js:18,38,41`. `clean()` keeps `\n` in `name`, which goes into `subject`. The email regex allows commas and angle brackets.
   - **Verified:** `"A\nBcc: x@y.z"` and `a,b@c.de` both pass validation.
   - **Impact:** Resend's JSON API makes real header injection unlikely, but it may reject these and the visitor sees "didn't send".
   - **Fix:** strip control characters from `name`, and use a stricter `reply_to` pattern such as `^[^\s@,;<>"]+@[^\s@,;<>"]+\.[^\s@,;<>"]+$`.
   - **Effort:** S

6. **Low: the contact form's email check differs between browser and server.**
   - **Evidence:** `ContactForm.svelte:20` uses `validity.typeMismatch`, which accepts `name@host`. The server requires a dot.
   - **Scenario:** the visitor gets the generic "Check your name, email address, and message." with no note on the email field.
   - **Fix:** use the server's regex on the client too.
   - **Effort:** S

7. **Low: the Ascii field throws after unmount.**
   - **Evidence:** `src/lib/components/Ascii.svelte:250,252` and `resize()` at line 227. The mountain picture's `onload` and `document.fonts.ready.then(queueResize)` are never cancelled. If they fire after unmount, `host` is null.
   - **Verified:** with the picture delayed 2 s, going Work → Home → Contact threw `Cannot read properties of null (reading 'getBoundingClientRect')`.
   - **Fix:** add a `destroyed` flag checked in `queueResize`/`resize`, and set `mountainImg.onload = null` in the cleanup.
   - **Effort:** S

8. **Low: unused dependencies.**
   - **Evidence:** `package.json`. `@fontsource/jersey-25` and `@fontsource/silkscreen` are referenced nowhere in `src`, `tools` or `api`. AGENTS.md also says those faces were removed.
   - **Fix:** remove both.
   - **Effort:** S

9. **Low (accessibility): some labels are never announced.** `aria-label` on elements with no role isn't exposed to screen readers.
   - **Evidence:** `Code.svelte:26` puts it on a `<pre>`, so labels like "The result" and ".mcp.json" on `/toolbox/agents/` are silent. `+layout.svelte:142` puts `aria-label="Status"` on a plain `div`.
   - **Fix:** use `role="region"` (or a `<figure>` with `<figcaption>`) on Code. Drop the label on the status strip, or give it `role="group"`.
   - **Effort:** S

10. **Low (accessibility): the Toolbox settings rows are invalid HTML.**
    - **Evidence:** `toolbox/AppToggle.svelte:21-24`. A `<label>` wraps both the switch and the format-chip buttons, but a label may contain only its one control.
    - **Impact:** the switch's accessible name absorbs the chip text, e.g. "Web JPEG PNG SVG".
    - **Fix:** name the switch with `aria-labelledby` on the row text, and move the chips outside the label.
    - **Effort:** M

11. **Low (accessibility): the texture still animates with Motion set to off.**
    - **Evidence:** `Ascii.svelte:76-78,111`. With `motion.on === false`, pointer heat trails and click rings still run on a 16 ms interval for about 2.5 s.
    - **Impact:** someone with reduced motion, or who turned Motion off, still gets movement on every hover and click (WCAG 2.3.3).
    - **Fix:** with motion off, apply heat in a single redraw with no decay loop, and skip the rings.
    - **Effort:** S

12. **Low: anyone can write fake referrer names into the admin dashboard.**
    - **Evidence:** `src/lib/analytics.ts:16-17` and `src/lib/server/analytics.ts:33`. Any request that sends a matching `Origin` header (e.g. from curl) can store any hostname as a referrer, up to 60 a minute per IP, kept for 366 days.
    - **Impact:** the admin Referrals table is junk, and the daily hash grows without limit. There's no XSS; it renders as text.
    - **Fix:** cap the number of distinct referrer fields per day (e.g. `HLEN` < 500), or keep only an allowlist of known hosts plus "other".
    - **Effort:** S

13. **Low (hardening): no Content-Security-Policy.**
    - **Evidence:** `vercel.json` headers, confirmed on the live site's response headers.
    - **Fix:** add a CSP with a hash for the inline theme script in `src/app.html:13`. Allow `api.github.com` only for the admin page, which fetches it server-side, so it isn't needed for `connect-src`. Try it as `Content-Security-Policy-Report-Only` first.
    - **Effort:** M

## Findings, highest impact first

1. **High: the desktop xrp.cafe video is 8.5 MB for a 326×576 box.**
   - Evidence: `xrpcafe-explore-create-trade.mp4` is 1080×1920 at 6 Mbps for 11.5 s. It sits at top 784px on desktop, so it autoplays almost at once. A full scroll of the page transferred 9.0 MB. At DPR 2 the box needs about 652×1152.
   - Fix: re-encode for desktop. My test encodes: 720w at CRF 24 is 0.78 MB; full size at CRF 24 is 1.25 MB.
   - Gain: about 7.7 MB per desktop visit. Effort S.

2. **High: the canvas knockout is recalculated for every visible cell on every tick.**
   - Evidence (steady-state profile, 4×): `knockout()` is 25% of main-thread time on desktop Home (704 ms in 8 s), 28% on mobile Home, 23% on Contact.
   - Cause: `rebuild()` in `src/lib/components/Ascii.svelte` re-runs `measure()` and `knockout()` per row each tick, even when the text boxes haven't moved. `knockout()` in `src/lib/knockout.ts` runs `Math.hypot` against every box, even far-away ones.
   - Fix:
     - Keep the per-cell knockout values and recompute only when the measured boxes change.
     - Skip boxes that are further than pad + feather + radius before calling `hypot`.
     - Copy props into locals at the top of `draw()`/`rebuild()`; Svelte's prop getter alone is another 3–6%.
   - Gain: about −25–30% of canvas CPU (desktop Home ~35% → ~25% at 4×). Effort S.

3. **High: the PARC study-head scene is half the main-thread time on that page.**
   - Evidence: the `parc` scene in `src/lib/studyScenes.ts` (lines 131–136) runs 6 fronds × 5 `seg()` calls plus trig for every cell, every 90 ms tick (`TICK_FAST`), with no bounds check. It is 47% of busy time (1392 ms in 8 s); desktop /work/parc/ is 35.6% busy at 4× and 15.4% at 1×.
   - Fix: skip the frond loop for cells outside a small box around the crown (about ±0.15), and work out the frond lines once per tick instead of per cell. The other study scenes probably have the same pattern; I didn't check them.
   - Gain: desktop PARC idle cost ~35% → ~19% at 4× (estimate). Effort S.

4. **High: canvas backing stores are sized at device DPR for art that is whole CSS pixels.**
   - Evidence:

     | Page | Canvas backing store |
     |---|---|
     | Mobile Home | 784×6672 = 20 MB |
     | Mobile Contact | 1176×3168 = 14.2 MB |
     | Desktop Home | 1440×2920 = 16 MB |
     | Each study head (mobile) | 3.2 MB |

   - Why it's safe: with `cell=8`, `px=1` and dither half-cells of 4px, every pixel is a whole CSS pixel, and the canvas already uses `image-rendering: pixelated`.
   - Fix: use a 1× backing store in `resize()`. It should look the same on 2×/3× screens; check on a real phone.
   - Gain: memory ÷4 on mobile Home (→ 5 MB), ÷9 on Contact (→ 1.6 MB) and study heads (→ 0.35 MB), plus less clear/fill work per tick. That work falls under "(program)", 23–36% of busy time. Effort S.
